## CHANGELOG bullets ("What you'd see" rows and itemized changes)

### What you'd see

| Situation | Before | Now |
|---|---|---|
| A brain with `embedding_query_prefix` set runs `gbrain think`, MCP `think`, `synthesize`, CRAG think escalation or dream auto-think | the question's takes vector embedded without the prefix | embedded with the brain's prefix, like hybrid search |
| `gbrain takes search --semantic`, `gbrain search diagnose`, eval's vector baseline, `gbrain brainstorm` on a prefix brain | bare query embedding | prefixed query embedding (saved eval baselines on prefix brains move) |
| A broad hybrid keyword search on a large Postgres brain times out, then the same search runs again in the same `gbrain serve` / MCP process | waits the full `search.keyword_statement_timeout_ms` again and times out again | answers at once from the vector arm with `keyword_arm_failed: skipped_after_timeout` for 10 minutes (`search.keyword_timeout_negative_cache_seconds`, 0 = off); a narrower or differently scoped query still runs keyword search |
| `recall --question` on an embedding model whose fact admission floors were never measured | nothing says the floors are unmeasured | an informational `facts_calibration: {status: "unmeasured", model_key}` field on every such call, and one `facts_calibration_unmeasured` info notice per session pointing at `gbrain doctor --only fact_admission_floors` |

### Itemized changes

- `src/core/search/query-prefix.ts`: `embedQueryWithPrefix(engine, text, opts?)` loads the brain's `embedding_query_prefix` and embeds with the unbounded `embedQuery`, so each caller keeps its deadline behavior. Swapped in at `ops/search.ts` (CRAG), `verbs.ts` (synthesize), `commands/think.ts`, `commands/takes.ts`, `ops/takes.ts` (MCP think), `cycle/auto-think.ts`, `commands/search-diagnose.ts`, `search/eval.ts` and `brainstorm/orchestrator.ts` (a ninth site the guard found). `test/query-embed-call-sites.test.ts` walks the AST and allowlists the remaining direct `embedQuery` / `embedQueryBounded` uses with reasons (#3783).
- `src/core/postgres-engine/keyword-timeout-cache.ts` (new): a per-engine negative cache keyed on the keyword statement text, its parameters, the RLS source scope and the statement timeout (strict and relaxed statements separately). Only a genuine statement-timeout 57014 records an entry, never a user or admin cancel; entries expire at the TTL, at most 256 per engine. Hybrid's keyword arm opts in (`SearchOpts.keywordTimeoutCache`) unless the call passed `useCache: false`; a skip reports `keyword_arm_failed` with the new degraded reason `skipped_after_timeout` and error code `keyword_skipped_after_timeout` (fix: `gbrain doctor --only keyword_plan --json`). No extra statement per search; the TTL is read on the first timeout and each timeout writes one bounded `search.keyword_timeout_stats` row, which doctor `keyword_plan` reports as `details.negative_cache`. New config key `search.keyword_timeout_negative_cache_seconds` (integer seconds, default 600, range 0-86400, 0 = off; `config set` refuses other values). Per process: `serve` and MCP benefit, one-shot CLI calls do not. Postgres only (#6495).
- `src/core/facts/question-recall.ts`, `src/core/ops/facts.ts`, `src/core/verbs.ts`: recall's informational `facts_calibration` (declared in `RESPONSE_SCHEMAS`, `docs/protocol/MEMORY_VERBS_v1.md`, `docs/mcp/TOOL_REFERENCE.md`) and the `facts_calibration_unmeasured` info notice, deduped per brain per session through the notice ledger's `dedupe_key`. `facts_degraded` and `degraded_recall` are unchanged. `FACT_ADMISSION_FLOOR_EVIDENCE` moves to `search/fact-relevance.ts` so recall and doctor read one table (#6590).
- Tests: `test/query-prefix-call-sites.serial.test.ts` (eight paths record the prefix through a stubbed transport), `test/query-embed-call-sites.test.ts`, `test/keyword-timeout-negative-cache-6495.test.ts` (unit arm on an injected executor plus a Postgres arm with locked tables), `test/recall-facts-calibration-6590.test.ts`. Each fails on master.
- Docs: `docs/guides/troubleshooting.md` (keyword timeout section and symptom row: the skip, its key, its limits), `docs/mcp/TOOL_REFERENCE.md` (`search`/`query` keyword reason, recall `facts_calibration`), `docs/protocol/MEMORY_VERBS_v1.md` (field row), key-files entries.

## Proposed BEHAVIOR_CHANGES rows (`since:` left to the integrator)

- `think`, MCP `think`, `synthesize`, CRAG think escalation (`search.crag_think`), dream auto-think, `takes search --semantic`, `search diagnose`, `gbrain eval` vector baselines and `brainstorm` now embed their query with the brain's `embedding_query_prefix`, like hybrid search already did; on a brain with a prefix their retrieval shifts and saved eval baselines move.
- On Postgres, a hybrid keyword statement that hit `search.keyword_statement_timeout_ms` is skipped for `search.keyword_timeout_negative_cache_seconds` (default 600 s, 0 = off) in the same serving process when the same statement and scope run again: the search answers from the vector arm with `keyword_arm_failed: skipped_after_timeout` instead of waiting for the timeout. A narrower or differently scoped query, another brain and `use_cache: false` still run it; each timeout writes one `search.keyword_timeout_stats` row that doctor `keyword_plan` reports.
- `recall` with `question` adds an informational `facts_calibration: {status: "unmeasured", model_key}` when semantic matching ranked facts on an embedding model without measured admission floors, and shows one `facts_calibration_unmeasured` info notice per brain per session (mute with `gbrain notices mute facts_calibration_unmeasured`); `facts_degraded` is unchanged.
